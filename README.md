# Logic Forge Website
React + Vite + Tailwind + React Router + Framer Motion + Lucide.

## Prerequisites
Node.js 18+.

## Run
```
npm install
npm run dev      # development
npm run build    # production build in /dist
npm run preview  # preview the build
```

## Customize
- **Brand colors:** `tailwind.config.js` (navy, dark, cyan, electric, light).
- **Text:** pages in `src/pages`; contact details in `src/data.js` (`SITE`).
- **Pricing:** edit the `pricing` array in `src/data.js`.
- **Admin pages:** `/admin` is a compact overview. Use its admin navigation to open `/admin/inquiries`, `/admin/users`, `/admin/showcase`, `/admin/services`, and `/admin/contact-info`; each page contains only its related management tools. The public footer is hidden on admin routes.
- **User accounts:** users can register at `/signup` and sign in at `/login`; the user login/signup page has a separate **Admin login** button for `/admin/login`. In the Supabase SQL Editor, run `supabase/user_accounts.sql` first to create account profiles and the admin-role helper. Re-run it to enable profile edits. Then run (or rerun) `supabase/project_inquiries.sql`, `supabase/services.sql`, `supabase/site_showcase.sql`, and `supabase/contact_info.sql` to apply the admin-only access policies. Sign up with the account you want to use as the site administrator, confirm its email if required, then promote it in the SQL Editor with `update public.user_profiles set role = 'admin' where email = 'your-admin-email@example.com';`. Only accounts with the `admin` role can access the panel. `/admin/users` lists registered accounts and opens a profile/inquiry detail dialog; admins can edit a selected user's name and phone there. The signup trigger captures a user's name, email, phone, and signup date. Phone numbers are optional and, when provided, must contain 7–15 digits. Inquiry submissions made while signed in are linked to that account; the inquiry migration also links previous submissions when their email matches a Supabase Auth account.
- **User account and inquiry chat:** after signing in, users can open `/account` from the header account link. They can update their name and phone number and change their password after verifying their current password; admins can manage their own profile and password at `/admin/profile`. Email and account role cannot be changed through the profile form. Account inquiries and conversations update live. Admin inquiry lists, user profiles, services, contact information, showcase content, and conversations also subscribe to live Supabase changes. Run or re-run the SQL setup files below to add their tables to the `supabase_realtime` publication; Realtime also requires the corresponding Supabase tables and policies to be set up. Admins can open a chat from a registered user's inquiry in `/admin/inquiries`, send replies, and update its status to New, Processing, Completed, Rejected, or Closed. To enable messaging, live inquiry updates, and the inquiry status choices, run the latest `supabase/project_inquiries.sql` after `supabase/user_accounts.sql`.
- **Services:** run `supabase/user_accounts.sql` first, then `supabase/services.sql` in the Supabase SQL editor to create and seed the database catalog and admin-only management policy. Sign in as an administrator and open `/admin/services` to add, edit, reorder, hide, or delete services. The public service list, detail pages, homepage ticker, footer links, and contact dropdown use the same database catalog. Service records include a URL slug, title, card summary, full details, icon, feature list, display order, and visibility. The bundled catalog in `src/data.js` is used as a fallback if Supabase is unavailable.
- **FAQs / process:** maintained in `src/data.js`.
- **Public contact info:** run `supabase/user_accounts.sql` first, then `supabase/contact_info.sql` in the Supabase SQL editor, then edit the phone number and email at `/admin/contact-info`. The saved values update the public contact page, WhatsApp links, and footer; bundled defaults are used if Supabase is unavailable.
- **Add a project:** add an object to `projects` in `src/data.js` (unique `slug` and a category matching a filter in `src/pages/Projects.jsx`). Its filter and `/projects/<slug>` page appear automatically.
- **Contact form submissions:** copy `.env.example` to `.env`, add your Supabase project URL and publishable/anon key, and run `supabase/user_accounts.sql` followed by `supabase/project_inquiries.sql` in the Supabase SQL editor. The contact form validates and saves each inquiry to `public.project_inquiries`; signed-in admins can view and manage submissions at `/admin/inquiries`. Anonymous submissions remain available; signed-in submissions are associated with the user's account. Only admins can read or manage inquiry records. Re-run the SQL after policy changes. After a successful save, the contact page offers optional WhatsApp and email links.
- If the admin panel reports that `project_inquiries` is missing, run `supabase/project_inquiries.sql` in the correct Supabase project (`elousemrmniyolefleii`) and retry. The dashboard cannot create its own table through the public browser key.
- **Project showcase images:** run `supabase/user_accounts.sql` first, then `supabase/site_showcase.sql` in the same Supabase SQL editor, then sign in as an administrator and open `/admin/showcase`. Select **Publish original screenshots** to seed the original website screenshot concepts for business, e-commerce, portfolio, restaurant, SaaS, and local services. Publishing restores all six defaults. The selected category's current screenshot is previewed on the showcase admin page only; it is not shown in the contact form. To replace one, choose its project/category, select a JPG, PNG, or WebP file up to 5 MB, and select **Upload & update**. The image is uploaded to the public `site-showcase-images` bucket and its project row, image path, and alt text are upserted in `public.site_showcase_projects`; the Projects page reads the saved screenshot from Supabase. Bundled screenshots are used if no database record exists.
